BATCH Processing :- Processing a finite dataset in one go.

* Data source -> Static files (Parquet, CSV, JSON, Delta) or a database snapshot.
* Run the job -> It reads all the data, processes it, and produces the output(load).
* No new data is considered after the job starts - if more data comes later, run job again

Pros:
* Simple, predictable (know what data is getting loaded, transformed)
* Good for large historical datasets
* Easier to debug and retry

Cons:
* High latency - we dont get results until the whole job finishes
* Not suited for near real-time data
-----------------------------------------------------------------------------------------------------

Stream Processing :- Processing unbounded, continuous data as it arrives

* Data source -> Kafka, Event Hubs, Kinesis, or files being written to a directory
* Job runs continously, processing new data in micro-batches or continous mode.
* Output/ Table updates in near real-time

Pros:
* Low latency - data is processed almost as soon as it arrives

Cons:
* More complex to design, debug and maintain
* Needs careful handling of late or duplicate data
-----------------------------------------------------------------------------------------------------

How do you handle data integration from multiple sources?

1. Identiy and connect to sources
    * Could be databases (MySQL, Postgres), APIs, files(CSV, JSON, Parquet), Streaming Systems(kafka)
    * Read whol data using connectors in PySpark/ Databricks:
        -> spark.read.format('jdbc') for database
        -> spark.read.format('json/parquet') for files
        -> Structured streaming for kafka/Event hubs

2. Ingest data into a single landing/ storage zone
    * store raw data in a centralized location (data lake)
    * Examples : AWS S3, Azure Data Lake, GCP cloud storage

3. Normalize and Standardize
    * Different sources may have: Different schemas (column names, data types)
    * Transform to a common schema using pyspark:
        -> Rename columns, convert data types, Handle nulls/missing fields

4. Merge/ join datasets
    * Use joins, unions, or MERGE to combine data into integrated tables

5. Load into target tables

6. Automate & Schedule
